# ADR 0002：Remote 與 Sites 共用一份雲端帳本

日期：2026-10-04。狀態：**Proposed；方向已納入規劃，服務尚未建立與驗證。**

## 新需求與決策理由

使用者已接受 Remote 作主要紀錄入口，並明確希望第一版有簡單前端，能看圖表、補充備註或少量紀錄。前端從延後選項變為第一版需求。

這改變了 ADR 0001 的儲存前提：Mac 本機正式帳本加上可編輯的網站副本，需要處理雙向同步、更新衝突、刪除傳播與過期資料。現在建議將唯一正式帳本放在 Sites 支援的 D1，Mac 與網站都透過同一套後端規則讀寫。

## 建議架構

```text
iPhone 照片／短句 → Codex Remote → Mac 上的 Codex 解析
                                      ↓ 受驗證的讀寫工具
手機／電腦的 Sites 前端 ←→ 同一套帳本服務 ←→ D1 雲端資料庫
                                      ↑
                           日期／份量／累計／版本／進階規則

Mac 私人目錄：原始附件、明確標為未送出的草稿、匯出備份
```

- D1 是 Sites 提供的持久資料庫，保存結構化紀錄，不需另外建立 Supabase 專案。D1 才是正式記錄的唯一來源。
- 原始照片先保留 Mac，不上傳 Sites。網站顯示分析項目、數值、來源及不確定性；不顯示無法存取的本機檔案連結或假縮圖。
- R2 是 Sites 提供的檔案儲存。若以後要手機網頁看原始餐照，再評估增加 R2；首版不建立這項資源。
- Sites 後端需使用相容的 JavaScript／TypeScript 執行環境。計算規則集中於 TypeScript 服務，由前端與工具共用；不另建 Python 計算副本。若需要 Mac 腳本，只負責傳輸、附件處理與重試。
- 模型辨識與教練式解釋仍在 Codex 執行。網站只讀寫及畫圖，不在開頁或更新資料時呼叫模型 API。

## Remote 如何寫入

建議提供 Site-hosted MCP 工具；MCP 是讓 Codex 呼叫受限制功能的工具介面，例如保存餐點、查詢今日累計。只提供業務操作，不開放任意 SQL 或 shell。

依已安裝 Sites MCP 技能，Sites 可提供私人 plugin 與平台管理的登入連線。實作時先建立並驗證受保護的讀取，再驗證寫入；不假設工具已安裝或帳號權限已完成。沒有真實登入身分的資料操作應拒絕，不能為了接通而改為公開。若平台連線不可用，再評估其支援的 owner-private service access；不提前同時實作兩種認證。

MCP 工具與前端 API 共用驗證、運算、權限與版本邏輯。保存每筆回傳 record_id、revision、saved_at；Mac 查讀確認雲端寫入成功後才回報「已記錄」。工具名稱與具體 schema 在實作時確定。

## 第一版前端範圍

一個手機可用的 dashboard，用三個區塊／分頁即可：

1. **今日**：課表、已完成／部分／休息、已回報餐數、攝取營養範圍、待確認項目、最近更新時間。
2. **紀錄**：依日期查看餐點與訓練；修正份量、補體重／腰圍、加一則當日或特定紀錄備註。自由文字備註不會自動成為另一筆攝取或訓練紀錄。
3. **趨勢**：體重原始量測及有效七日平均、腰圍、近期訓練次數與同動作負荷／次數、每日已回報營養。資料不足就顯示空狀態；不同負荷模式不能混在同一比較。

先用開頁、回到頁面與按下更新時重新取得資料，前端自身保存後立即重抓；不承諾跨裝置秒級推播。每次寫入只是更新運行中的資料，不需重新部署網站。程式或 schema 改變才部署。

網站上的補充在下一次 Remote 查詢時可見；不是背景自動喚醒 Codex。計畫建議繼續要求使用者確認，不因網站編輯而偷偷更換熱量或負荷。

## 失敗與離線

Mac 關機時，已保存的雲端紀錄仍可在網站查看，網站的基本手動補充仍由雲端處理。照片 AI 分析需要可用的 Codex 執行主機。

雲端寫入失敗時，Mac 可留待送出草稿；它不算第二份正式帳本，狀態須寫「待送出」。重試沿用同一 request_id。若傳送成功但收據遺失，查詢或重試同 ID，不另建紀錄。

兩個入口同時修改時使用 expected_revision 檢查；舊版本不得覆蓋新資料，應讀取最新版本並呈現差異。不建立完整離線雙向同步系統。

## 私密資料邊界

正式上線前以非個人合成資料驗證存取。Sites 設為私人且只授權本人使用，並核對帳號所在 workspace 的管理員可見性；不可承諾平台管理員絕對無法存取。

只匯入必要的普通運動、飲食、量測與計畫欄位。私人交接稿、整段對話、性健康背景、病史與醫療備註不打包進 Site、D1、MCP 回覆或一般 log。自由文字補充不得預設收集這些敏感背景，提交前清楚說明會保存到雲端。

Sites 官方禁止處理 Protected Health Information（受特定規範保護的健康資訊），也沒有資料／推論地域保證。不將這段文件解讀成「所有個人健身紀錄一律禁止」或「私人 Site 就能忽略限制」。若未來需要受限制的醫療資料，應重新選擇儲存／託管，不直接擴張這個 Site 的範圍。

匯出／刪除需說明 D1 紀錄、Mac 原始照片、待送出草稿與備份各自的範圍；遠端刪除在 Mac 離線時不能冒稱本機附件已刪除。雲端持久化不取代獨立備份／復原驗證。

## 費用與尚待驗證

網站展示、查詢、保存與畫圖是程式運算，本設計不額外呼叫付費模型 API。Codex 分析仍用登入方式所對應的方案用量；Sites 託管與儲存另受 Sites 方案限制，不承諾無上限或永久免費。

待實作驗證：此帳號可建立私人 Site／D1、原生 plugin 的登入與工具可用性、iPhone 附件持久保存、兩入口權限與一致性、實際儲存配額及備份路徑。
